# Conditioned Signed-State Replay Protocol

Status: preregistered implementation protocol; no conditioned live results recorded yet.

## Claim boundary

The experiment tests whether a later model call can emit a boundary-delimited recovery candidate when given provider-signed reasoning state. It does not establish ground-truth chain-of-thought recovery, byte fidelity, or provenance of every recovered token. Every public artifact must therefore set `ground_truth_cot_proven: false` and use the claim `signature_backed_recovery_candidate`.

## Exact sequential lineage

For each Fermi task, R1 answers the original question. R2 re-estimates it through a different quantitative route. R3 reconciles R1 and R2. Each round is generated by a new Bedrock Converse request whose history contains the exact complete responses returned by all preceding rounds. R4 is the recovery follow-up appended after R3.

The primary `signed_priming` condition must preserve the exact R1/R2/R3 message lineage, including every signed reasoning block and provider summary. Any transformation is an ablation and must be labeled as a protocol deviation.

## Paired R4 conditions

- `direct`: R4 targets R1 in a fresh process/client; the provider summary is blinded.
- `signed_priming`: R4 targets R3 after the exact complete signed R1/R2/R3 lineage. This is the primary condition.
- `signed_priming_blinded`: the same R3 target with all provider reasoning summaries blanked while signatures remain.
- `text_only_priming`: R1/R2 reasoning blocks are removed; R3 remains signed with its provider summary blanked.
- `unsigned_target`: exact signed R1/R2 prefix, but the R3 reasoning block is removed.
- `corrupted_target`: exact signed R1/R2 prefix, but one character of the R3 signature is changed.

Every condition uses a fresh Bedrock client. Provider rejection is an observed outcome, not a retry trigger. Raw signatures and full condition responses remain in ignored private artifacts with mode `0600`; public summaries contain hashes, counts, metrics, and explicit deviations only.

## Completion criteria

The protocol is complete when both configured Fermi tasks have three signed, exact sequential harvest rounds and all required paired conditions (`direct`, `signed_priming`, `text_only_priming`, `unsigned_target`, and `corrupted_target`) have either returned an observation or an explicit provider rejection. Canary boundaries validate output extent only; they do not prove content provenance.
